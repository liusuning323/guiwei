第一次使用，只需三步：

```bash
# 1. 下载 & 安装
# 从 Releases 下载 → 解压 → 拖入 /Applications

# 2. （可选）安装增强依赖，让归位能读懂 PDF 和 Word
```

安装完成后，推荐先从 **模式 1（仅重命名）** 开始试手——最安全，只改名不挪位置。

## 它能做什么

| 模式 | 功能 | 适用场景 |
|------|------|---------|
| **1 - 仅重命名** | 按规范改名，文件留在原地 | 文件还在处理，先规范个名字 |
| **2 - 智能归档** | 读内容 → 改名 → 归入 Documents | 文件已完工，永久归档 |
| **3 - 快速查阅** | 只看内容预览和分类建议，不动手 | "这文件是什么来着？" |
| **4 - Inbox清空** | 自动扫描 `00_inbox`，批量归档 | 每周维护，清空待处理 |
| **5 - 桌面清理** | 扫描 Desktop 散落文件，批量归档 | 桌面又堆满了 |
| **6 - 批量重命名** | 整个文件夹统一改名（含递归子文件夹） | 一堆截图/文档统一规范命名 |

## 核心能力

- **📖 读内容** - 用 macOS Spotlight + pdfplumber + python-docx 提取文件内容
- **🧠 智能分类** - 50+ 学术关键词图谱，基于文件名 + 内容双重评分
- **🏷️ 自动重命名** - 6 套命名规范，自动清理 Screenshot/微信图片 等前缀
- **🔄 递归扫描** - 支持嵌套子文件夹深度处理
- **💻 100% 本地** - 零联网，零 API 调用，不耗 token

## 安装

### 方式一：下载 Release（推荐）

从 [Releases](https://github.com/liusuning323/归位-guiwei/releases) 下载最新 `.app`，拖入 `/Applications`。

首次打开如果提示"未验证的开发者"：

1. 右键 `归位.app` → **打开**
2. 在弹出的对话框中点 **打开**

### 方式二：自行构建

```bash
git clone https://github.com/liusuning323/归位-guiwei.git
cd 归位-guiwei
chmod +x build.sh
./build.sh
```

构建产物在 `build/` 目录下。

## 使用演示

以一个真实的文件整理场景为例：

```
📥 你在桌面下载了一篇论文 PDF: "s2312-3456-89-1-1.pdf"

1. 拖拽文件到 归位.app 图标上
2. 终端自动打开 → 选择模式 2（智能归档）
3. 归位开始分析：
   → macOS Spotlight 提取元数据
   → pdfplumber 读取正文关键词 (Biesta, education, accountability...)
   → 匹配到 "文献 literature" 分类
   → 建议命名: "2026-05-03_Biesta_Education.pdf"
4. 按 R 确认 → 文件自动归入 ~/Documents/03 资源 resources/文献 literature/
```

如果你想先看看这是个什么文件，选模式 3（快速查阅）：

```
📄 s2312-3456-89-1-1.pdf
   作者: Biesta, G.J.J.
   来源: https://doi.org/10.1080/...
   识别为: literature
   建议名: 2026-05-03_Biesta_Education.pdf
   建议路径: ~/Documents/03 资源 resources/文献 literature/

   (R)切归档处理  (N)切重命名  (Q)跳过
```

**每次操作都有确认环节，不会擅自移动你的文件。**

## 系统要求与边界说明

### 运行环境

| 项目 | 要求 |
|------|------|
| 操作系统 | macOS 12.0+（Apple Silicon / Intel） |
| Python | 3.10+（macOS 预装，无需额外安装） |
| 可选依赖 | `pdfplumber` `python-docx` `Pillow`（增强内容识别） |
| 磁盘空间 | ~5 MB（应用本身） |
| 网络 | 不需要（全程本地运行） |

### 安装可选依赖

```bash
pip3 install pdfplumber python-docx Pillow
```

> **注意：** 不安装也不影响核心功能。归位仍然会用 macOS Spotlight 读取文件元数据，只是遇到无命名的 PDF 时会归入 `inbox` 而不是自动分类。

### ❓ 常见问题

**Q: 第一次打开提示"无法验证开发者"？**
A: 这是 macOS 的安全机制。右键 `归位.app` → **打开** → 在弹出的对话框中点 **打开**。只需要操作一次，之后双击即可正常启动。

**Q: 可以不装 Python 依赖直接用吗？**
A: 可以。归位会自动用 macOS Spotlight 读取文件信息。装了依赖后能读 PDF 正文和 Word 文档内容，分类更精准。

**Q: 模式之间怎么切换？**
A: 启动时选模式。每个文件处理时也可以用快捷键临时切换：在模式 1 按 `A` 切归档，在模式 2 按 `1` 切重命名。

**Q: 文件移动错了能恢复吗？**
A: 每次操作前都有确认环节。如果已经移动了，去目标文件夹手动移回即可。推荐先在模式 3（快速查阅）预览后再操作。

**Q: 归位会影响我原有的文件夹结构吗？**
A: 不会。归位只移动你指定处理的文件，不会修改已有的文件夹结构或删除任何文件（除非你主动确认）。

**Q: 为什么我的 PDF 没有被正确分类？**
A: 可能原因：(1) 未安装 `pdfplumber`；(2) Spotlight 尚未完成索引（新文件需要等待几秒）；(3) 文件内容为扫描件（图片型 PDF）无法提取文字。

**Q: 隐私安全吗？**
A: 归位 100% 本地运行，不联网、不发送任何数据、不调用任何 API。代码完全开源，可在 GitHub 审查。

```
~/Documents/
├── 00 待处理 inbox/
├── 01 项目 projects/
├── 02 领域 areas/
├── 03 资源 resources/
├── 04 归档 archives/
├── 05 个人 personal/
├── 06 代码 code/
├── 07 应用 apps/
└── 99 系统 system/
```

配合 [Obsidian](https://obsidian.md) 使用效果更佳 — 笔记层（Obsidian）+ 存储层（文件系统），PARA 统一分类。
